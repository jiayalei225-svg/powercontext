1. 模型与量化 MODEL

模型：BAAI/bge-small-zh-v1.5（4 层 BERT，hidden 512，max 512 token，MIT）；ONNX 版 Xenova/bge-small-zh-v1.5 @ 75c43b06。CLS pooling + L2 normalize；query 侧加官方检索 instruction，文档侧不加。

量化：ONNX Runtime dynamic quantization，weight-only、QUInt8、per-channel；独立复现 artifact 24,020,718 B，与提交件相差 0.041%，合成输入 cosine 0.9978。另提供 FP16 权重。

质量：FP32 nDCG@5 0.884 → INT8 0.878（−0.69%）；Recall@5 均为 0.950；FP16 与 FP32 排名一致。评测集 20 queries / 27 docs / topK=5。

2. 端侧运行与降级 RUNTIME

Transformers.js 4.3.2 + ONNX Runtime Web，全部在 Dedicated Worker 内完成；allowRemoteModels=false，同源加载 ONNX 与 ORT wasm。

自动探测 navigator.gpu / requestAdapter()：成功则 WebGPU + FP16；无 adapter、无 navigator.gpu 或会话失败则自动重建 WASM session，保留已有 collection 的 FP16 精度，并显示实际后端、精度、device 与降级原因。

WASM 4 threads（COOP/COEP）；无 GPU 实测 HUD WASM / FP16，adapter 返回 null 的提示可见，检索继续。

3. seekdb 数据层 STORAGE

每个知识库独立 collection：HNSW(512, cosine, M=16, efC=200, efS=100) + IK smart 全文索引；embeddingFunction=null，向量仅在浏览器生成。块保存原文、向量与 docId/title/chunkIndex/charStart/precision 元数据；注册表保存集合标题与计数。

检索：collection.hybridSearch({ query:{whereDocument:{$contains:...}}, knn:{queryEmbeddings:[...]}, rank:{rrf:{rankWindowSize:40, rankConstant:60}} })。两路召回、过滤、RRF 融合均由 seekdb DBMS_HYBRID_SEARCH 完成，客户端只按 docId 聚合。

写入：16 块/批 add，同 docId 先删旧块；完成后 refresh_index()，用新块自身向量做 topK 自查询验证，失败重试并清理；注册表同步更新。增量导入、替换和集合切换后的结果均按当前 collection 隔离。

同设备、同语料、同 query 集、同 seekdb 索引；p50 为 20 条 query 的中位数；batch 吞吐为 36 个固定块、预热后两轮中位数。设备：Ryzen 9 8940HX / RTX 5060 Laptop / Edge 156 headless / 16GB。

  • WebGPU 的 batch 16 吞吐为 WASM 的 31×（70.89 vs 2.26 texts/s），batch 32 反而回落到 49.75/s，默认工作点选 16。
  • INT8 的主要收益是体积（3.90×）和加载；本机 ORT Web WASM 的单条吞吐没有优势，报告保留事实，不把“更小”写成“更快”。
  • 单条查询编码约 78 ms，端到端 150–191 ms；WebGPU 的收益集中在文档批处理，而非单条 kernel launch。
  • 冷/热初始化（同会话重载）：20.92 s → 17.91 s；ONNX 以 no-store 提供，规避 Chromium 大 body 的 ERR_CACHE_WRITE_FAILURE，热启动收益来自连接与浏览器内部缓存。
  • 混合检索 vs 单路（FP32）：Hybrid / Vector Recall@5 = 0.950 / 0.925，nDCG@5 = 0.884 / 0.819；RRF 兼顾召回与排序。

5. 状态、刷新与可复现 STATE

  • 集合注册表持久化标题、文档数、块数、最近导入时间；切换只查询当前 collection。
  • 增量导入按 docId 替换；失败清理新块；刷新后自查询验证可检索。
  • npm install → npm run setup:model → docker compose up -d seekdb → npm run build && npm start。
  • 示例语料、20 条 qrels、原始 JSON/CSV、逐条指标与截图均在仓库 docs/。

边界：单用户本地演示，无公网鉴权；seekdb 使用 server 模式；推理 API 零云端调用；向量/原文/检索均通过 seekdb，不使用客户端内存或回放。
