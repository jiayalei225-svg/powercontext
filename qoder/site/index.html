文献检索，
应该告诉你答案在第几页。

PaperDesk 是一个本地优先的文献工作台：把 PDF 变成可检索的段落， 用 seekdb 做向量、关键词与条件过滤的混合检索， 用 PowerContext 记住你的检索习惯，下次自动生效。

01 · 问题

难的不是“没有搜索框”，是搜到了还得自己翻。

读研、写综述、跟课题时，文献通常散在十几个文件夹里。你记得“有一篇讲图神经网络过平滑的”， 但记不住标题，也记不住文件名。通用搜索给出的是整篇 PDF，接下来仍然是 Ctrl+F、翻页、再翻页。

更麻烦的是，检索条件其实很稳定：你常看某几个会议、只看近几年、偏好有开源代码的论文。 但每次打开一个新工具，这些偏好都要重新勾一遍，工具不会记住你。

  • 定位粗 返回整篇文档，答案在第 17 页还是第 2 页，全靠人找。
  • 只有一种召回路子 纯向量对专有名词和公式符号不敏感，纯关键词又接不住同义改写。
  • 每次都从零开始 年份、会议、是否开源这些条件，换一个入口就要重设一次。

02 · 能力

把三件事做扎实，不铺功能。

01

页级定位

PDF 按页解析、再切成约 360 字的段落。每个段落都带着论文标题、年份、会议、页码， 命中后直接给出原文片段并高亮关键词，不需要再打开文件。

02

混合检索

向量语义、全文关键词、元数据过滤三路一起进 seekdb。三路结果在库内用 RRF 融合， 而不是应用层各查一遍再拼接。年份、会议、领域、是否有代码都可以叠加。

03

记忆偏好

默认年份、常读会议、是否只看有代码的论文，写进 PowerContext。 下一次检索自动套用，并在结果上方逐条说明“这次按记忆改了什么”。

03 · 技术分工

两个指定技术，各管一段，而且真的串起来了。

记忆

PowerContext

偏好与检索留痕，带 revision 的 Memory 条目

偏好 JSON
编排

search.py

读最新偏好，转成 seekdb 的 where 条件

where + query
存储与检索

seekdb

hybrid_search：向量 + 全文 + 标量过滤，RRF 融合

seekdb

东西存在哪、怎么找

  • 嵌入式运行，数据落在 data/seekdb/，不需要 Docker 或独立服务。
  • 每个段落写入向量、原文与元数据；集合按嵌入模型命名，避免维度冲突。
  • 检索走 hybrid_search：向量 KNN、$contains 全文匹配、where 标量过滤，三路在库内融合。
  • 关键词取 query 中在当前语料里出现最少的实词，减少“神经网络”这类高频词带来的噪声。
PowerContext

你是谁、你习惯什么

  • 偏好以 JSON 写入 /v1/memory/remember，读取时取 saved_at 最新的一条。
  • 每次检索也记一条 progress 记忆，用于复盘“当时用了什么条件”。
  • PowerContext 停掉时检索照常可用，界面显示“记忆未连接”，属于刻意降级。
  • 记忆不是聊天摘要，而是可读、可核对的版本化条目，界面上能直接看到 artifact 与 revision。

因果关系是可验证的：同一句 query，写入偏好前后结果集不同。 不是“装了组件”“通了连接”，而是偏好真的改变了 seekdb 的过滤条件与返回结果。

性能也做了实测：一次检索的中位耗时从 6.5s 降到 115ms。 瓶颈不在 seekdb，而在每次检索新建 3 个 PowerContext 连接（本机建连约 1.5s）； 改成连接池、偏好 TTL 缓存和语料缓存后，检索路径只剩一次库内混合检索。

04 · 验证

一条 14 项断言的验收脚本，跑完给出证据。

  1. 导入样例4 篇自撰阅读笔记，共 12 个页级段落。
  2. 第一次检索清空偏好，检索“图神经网络为什么会过平滑”，命中 12 段，首条是 GNN 笔记第 2 页，未套用任何记忆。
  3. 写入偏好2020 年起、只看 NeurIPS、必须有代码，写入 PowerContext，返回 artifact 与 revision。
  4. 第二次检索同一句 query，自动套用记忆，结果从 12 段收缩到 3 段，且全部满足约束。
  5. 记忆留痕偏好条目与检索进度条目都能在 /api/memory 读到。
  6. 跨会话复用重新读取偏好，内容与写入一致，证明存在服务端而不是页面状态。

05 · 运行

不需要 Docker，也不需要数据库服务。

环境

  • Python 3.10–3.13（Windows 建议 64 位）
  • 首次启动联网下载约 90 MB 的中文向量模型，默认走镜像
  • 前端已提交构建产物，评委无需安装 Node
  • 可选：Node.js 20+，仅在修改前端时需要

Windows 一键启动

powershell -ExecutionPolicy Bypass -File scripts\start.ps1
.\.venv\Scripts\python.exe scripts\seed.py

打开 http://127.0.0.1:8080

macOS / Linux

bash scripts/start.sh
.venv/bin/python scripts/seed.py

脚本退出时会一并停掉它启动的 PowerContext。

两个容易踩的坑

  • Git Bash 启动 PowerContext 时，MSYS 会改写 /mcp 参数。先执行： export MSYS2_ENV_CONV_EXCL="POWERCONTEXT" export MSYS_NO_PATHCONV=1 或改用 PowerShell。
  • 模型下载默认使用 HF_ENDPOINT=https://hf-mirror.com； 下载失败会自动降级到 pyseekdb 自带的英文 MiniLM，应用仍可启动。

配置全部在 .env，示例文件只含占位值，不包含任何真实 API Key、密码或凭据。 完整的依赖版本、分步启动、接口说明与常见问题见仓库 README。

06 · 工程

结构清楚，依赖固定，状态可重置。

技术栈

  • 后端：Python 3.13、FastAPI、Uvicorn、PyMuPDF、jieba、httpx
  • 检索：pyseekdb 1.4.0、pylibseekdb 1.4.0（嵌入式 seekdb）
  • 记忆：PowerContext 1.4.1，内置 SQLite 后端
  • 前端：React 19、TypeScript 5.9、Vite 7、Tailwind CSS 4
  • 嵌入：本地 ONNX 中文 BGE 小模型（512 维），可切换任意 OpenAI 兼容接口

数据与来源

  • 样例 PDF 由 scripts/make_samples.py 现场生成，是本项目自撰的阅读笔记，未复制论文原文或第三方数据集。
  • 依赖均为开源项目，按原许可证使用：seekdb / pyseekdb、PowerContext、FastAPI、PyMuPDF、jieba、React、Vite、Tailwind CSS。
  • 仓库不含真实凭据；.env、data/seekdb/、data/uploads/ 已被忽略。
  • 演示用的偏好与索引都是可变状态，按 README 的步骤可以重置回初始状态。
