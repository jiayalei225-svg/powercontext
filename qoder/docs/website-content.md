## 3. 问题

### 标题

**学习资料很多，真正用起来的很少。**

### 三张卡片

**01 · 找一个概念，只能 Ctrl+F**  
讲义在 PDF、笔记在 Markdown、论文在另一个文件夹。记得意思，记不住原话，就搜不到。

**02 · 复习没有队列**  
熟悉的章节反复看，薄弱的章节下意识躲开。没有“今天该复习什么”，也没有“上次错在哪”。

**03 · 每个助手都从零开始**  
新开一个会话，就要重新交代“我在学什么、哪里不懂、希望怎么讲”。对话结束，经验也结束。

### 过渡句

这三件事不是三个功能，而是一条链路。缺任何一环，学习资料都只是“存着”。

## 4. 解决方案

### 标题

**一条闭环，从入库到下一次复习。**

### 流程

```
导入资料 → 混合检索 → 带记忆回答 → 会话收尾
   ↑                                      ↓
   └──── 掌握度 / SM-2 ← 原文出题 ← 今日队列
```

### 四张能力卡

**找得到：向量 + 全文 + 元数据**
问“正则化和过拟合是什么关系”，既按语义找，也按字面找，还能限定学科、文档、章节。每条结果都带 `doc_id / doc_title / section / page / chunk_id`，答案里的引用能回到原文。

**记得住：五类长期记忆**
会话结束不是清空，而是写回 PowerContext：你的讲解偏好、具体错因、本轮摘要、复习计划、任务进展。下一次提问，这些记忆会被召回并注入。

**会安排：掌握度 + 简化 SM-2**
答对加分、答错扣分、长期不练会衰减。下次复习从 1 天到 3 天，再按难度递增；答错的知识点 30 分钟后就回到队列，不给你“躲过去”的机会。

**可复核：四层技术轨迹**
每一次 seekdb 检索、PowerContext 读写、应用编排和模型调用都有 trace。前端抽屉里能看到 chunk 相似度、注入记忆的 kind 与正文，不靠“相信”。

## 5. 双引擎分工

### 标题

**seekdb 管知识，PowerContext 管你。**

### 对比表

| | seekdb | PowerContext |
| --- | --- | --- |
| 角色 | 知识底座 | 学习者上下文 |
| 存什么 | 原文 chunk、章节、页码、向量与全文索引；文档、知识点、题库、练习、掌握度、轨迹 | 学习偏好、薄弱点与错因、会话摘要、学习计划、任务进展 |
| 怎么用 | 混合检索 + 元数据过滤，结果可定位到 chunk | 语义召回 + 补读稳定偏好，注入提示词 |
| 谁写入 | 导入、判分、SM-2、队列 | 会话收尾、练习提交、计划生成 |
| 不可替代性 | 原文必须精确引用，不能靠模型记忆 | 用户状态是自然语言、会变化，必须跨会话召回 |

### 一次问答发生了什么

1. **seekdb**：BGE 向量分支 + jieba 关键词全文分支，加权 RRF 融合，返回可引用 chunk。
2. **PowerContext**：按问题召回相关记忆，再补读偏好、计划与任务进展，去重后注入提示词。
3. **回答**：有 LLM 时基于证据生成；没有时用原文与记忆拼装。两种模式都不编造。
4. **留痕**：四层 trace 落库，前端可逐条核对。

### 强调句

**不是“两个都调一下”，而是“知识归知识，人归人”。**

## 6. 功能深挖

### 6.1 混合检索

- 向量：本地 BGE-small-zh-v1.5 ONNX，512 维，首次运行自动下载，不需要外部 key。
- 全文：jieba 关键词 + 领域词典，避免“正则化”被切成“正则 / 化上”。
- 过滤：学科、文档、章节。
- 融合：`0.6 / (60 + 向量排名) + 0.4 / (60 + 全文排名)`，权重可在 `.env` 调整并复现。
- 输出：相似度、RRF 分、引用字段同时保留，技术轨迹可查。

### 6.2 记忆注入

- 五类 kind：`profile`、`weakness`、`session_summary`、`plan`、`task_state`。
- 语义召回最多 8 条，再补读近期偏好/计划/进展，去重后最多 10 条。
- 相同偏好与相同卡点幂等复用，不重复写。
- PowerContext 不可用时接口明确返回 503，不生成“看起来像记得”的假回答。

### 6.3 出题与判分

- 题目不是手写题库：从真实 chunk 生成“原文找知识点”和“知识点找原文”两种题。
- 干扰项来自其他知识点，选项按题目 ID 确定性打乱。
- 判分在服务端；每题返回正确答案、解释、引用 chunk、掌握度变化与下次复习时间。
- 答错自动写 `weakness`，当天练习写 `task_state`。

### 6.4 调度与计划

- 掌握度 0–1，答对 `score += 0.25 × (1 − score)`，答错 `score ×= 0.8`。
- 14 天未练习按 `0.85 ^ (天数 / 14)` 衰减。
- 间隔 1 天 → 3 天 → 间隔 × ease；答错 30 分钟后重来。
- 今日队列：未练习优先、低分优先、到期早优先。
- 三天计划按实时队列生成并写入 PowerContext；重复点击复用同一条。

## 7. 90 秒演示脚本

> 适合录屏或现场演示。每一步都指向界面上真实存在的位置。

**0:00–0:10 · 开场**  
“学习资料散、复习靠感觉、AI 没记性。StudyCoach 把这三件事接成一条闭环。”

**0:10–0:25 · 资料入库**  
进入「资料库」→「导入示例资料」。  
“三份讲义进来，27 个 chunk，按章节和页码切好，向量与全文索引同时建立。”

**0:25–0:45 · 带记忆回答**  
进入「问答」，问“正则化和过拟合是什么关系”。  
“回答先给结论，再落到原文。右边能看到引用了哪些 chunk。注意，它还会先说我上次卡在哪。”

**0:45–1:00 · 收尾写记忆**  
点「结束本轮」，填写卡点和偏好并提交。  
“这一轮不是结束就消失：摘要、错因、偏好都写进 PowerContext。”

**1:00–1:18 · 复习与判分**  
进入「今日复习」→「开始 5 题」，故意答错一题并提交。  
“题目来自原文。答错后掌握度从 40% 降到 32%，30 分钟后重新进队列。”

**1:18–1:30 · 计划与轨迹**  
点「生成 3 天计划」，再打开「技术轨迹」。  
“计划写回 PowerContext；轨迹里能看到每一次 seekdb 检索和记忆读写。不是黑盒。”

**收尾**  
“seekdb 管知识，PowerContext 管你。这就是 StudyCoach。”

## 8. 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Python 3.11+ · FastAPI · Uvicorn |
| 知识库 | 嵌入式 seekdb（pyseekdb + pylibseekdb） |
| 记忆 | PowerContext 1.4.1（项目专用实例，8010） |
| 嵌入 | BGE-small-zh-v1.5 ONNX，512 维，本地运行 |
| 检索 | 向量 + 全文 + 元数据过滤，加权 RRF |
| 调度 | 掌握度评分 + 简化 SM-2 |
| 前端 | 原生 HTML / CSS / JavaScript，无构建链 |
| 运行 | Windows / macOS 一键脚本；Docker 为未验证备选 |

### 工程细节

- 克隆后 `pip install -r requirements.txt` 即可运行，seekdb 无需单独服务。
- 启动顺序固定为 app → PowerContext，避免嵌入探针超时导致记忆降级。
- 时间统一 UTC：Python 写 naive UTC，SQL 用 `UTC_TIMESTAMP(6)` / `UTC_DATE()`。
- `.env.example` 只含占位值，真实配置被 git 忽略。

## 10. 诚实边界

- **LLM 可选**：未配置 key 时是 evidence 模式，答案由原文与记忆拼装；不会假装生成了模型回答。
- **收尾规则化**：偏好识别用显式规则，卡点来自用户输入；没有 LLM 时不做“推断用户没说过的事”。
- **PDF 仅文本层**：扫描件需要 OCR，当前不支持。
- **单用户本地**：面向个人学习工作台，多用户隔离不在本次范围。
- **Docker 未验证**：主路径是嵌入式一键启动；容器编排作为备选提供，并在 README 明确标注未在本机验证。

## 12. 常见问题

**Q：没有大模型 API key 能用吗？**  
能。默认 evidence 模式，回答由检索原文与记忆拼装，界面会标注模式；配置 OpenAI 兼容端点后自动切换。

**Q：为什么不用一个数据库全做完？**  
原文需要精确引用与页码，适合 seekdb 的 chunk + 索引；学习者状态是自然语言、会演化，适合 PowerContext 的语义记忆。分工让两边都可解释。

**Q：记忆会不会越写越乱？**  
相同偏好与卡点幂等复用；练习只写当天进展和最多 3 条错因；计划相同文本直接复用。前端可逐条查看与核对。

**Q：怎么证明检索和记忆真的发生了？**  
技术轨迹记录每次操作的输入、条数、摘要与 payload；`scripts/verify.py` 会自动断言 trace、引用字段、记忆 kind 与掌握度变化。
